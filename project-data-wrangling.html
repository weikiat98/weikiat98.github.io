Due to the presence of special symbols (the pipe | character) from data entries in columns 4 to 11, the data type is stored as text. The headcount column is also text even though the data entries are whole numbers.

Step 03 — Alter Table

The first step is to create a duplicate copy of the original data table tma_data called tma_data2. This preserves the original data as a backup in case of errors during transformation.

MySQL 
-- Create duplicate tma_data
CREATE TABLE tma_data2 AS
SELECT * FROM tma_data;

-- Renaming columns to lowercase
ALTER TABLE tma_data2
  RENAME COLUMN Office TO office,
  RENAME COLUMN Department TO department;

-- Modifying headcount data type to INT
ALTER TABLE tma_data2
  MODIFY COLUMN headcount INT;

-- Trimming whitespace from string columns
UPDATE tma_data2
SET office = TRIM(office),
    department = TRIM(department);

Column names Office and Department are renamed to lowercase to standardise letter case across all column names. The headcount data type is changed to integer since the entries are all whole numbers. Whitespace is trimmed from office and department columns to prevent matching errors.

Design Decision

Only headcount was changed to integer since the column is entirely whole numbers. With only 12 rows, the dataset is small enough that keeping other columns as text has negligible storage impact. The xx|yy|zz format in columns 4–11 requires text to preserve the pipe-delimited structure until the values are properly split in Question 1(b).

Question 1(b)

Recomputing All Totals

Task Using appropriate MySQL statements, recompute all the totals columns in the TMA_data table, and update the table with these recomputed values.
Step 01 — Create New Columns

Entries with the pattern xx|yy|zz are split into individual columns. xx refers to total number of offers made or accepted, yy to senior positions, and zz to inclusive positions.

For each recruitment firm, new columns are created following a clear naming convention: offers_recruitment_firm1_total, offers_recruitment_firm1_senior, and offers_recruitment_firm1_inclusive.

MySQL 
-- Add new columns for offers and acceptances
ALTER TABLE TMA_data2
  ADD COLUMN offers_recruitment_firm1_total INT,
  ADD COLUMN offers_recruitment_firm1_senior INT,
  ADD COLUMN offers_recruitment_firm1_inclusive INT,
  -- ... repeated for firm2, firm3, and totals
  ADD COLUMN acceptance_total_total INT,
  ADD COLUMN acceptance_total_senior INT,
  ADD COLUMN acceptance_total_inclusive INT;
📸
Image placeholder — Figure 5
Figure 5: Creating new columns as part of splitting the data from column 4 to 11
Step 02 — Populate with Split Values

Using SUBSTRING_INDEX to extract each value from the pipe-delimited format, and CONVERT with UNSIGNED INTEGER to cast the extracted text into integers.

MySQL 
-- Populate new columns with split values
UPDATE tma_data2
SET
  offers_recruitment_firm1_total =
    CONVERT(SUBSTRING_INDEX(offers_recruitment_firm1, '|', 1), UNSIGNED INTEGER),
  offers_recruitment_firm1_senior =
    CONVERT(SUBSTRING_INDEX(SUBSTRING_INDEX(offers_recruitment_firm1, '|', 2), '|', -1), UNSIGNED INTEGER),
  offers_recruitment_firm1_inclusive =
    CONVERT(SUBSTRING_INDEX(offers_recruitment_firm1, '|', -1), UNSIGNED INTEGER),
  -- ... repeated for all firms and acceptance columns

Step 01 — Insert Total Rows

Three new "Total" rows are inserted for Singapore, Hong Kong, and Tokyo. Each total row aggregates the values across all departments for that office location using SUM() functions, while original pipe-delimited columns are set to NULL.

📸
Image placeholder — Figure 11
Figure 11: Inserting the row and the contents the row should have
MySQL 
-- Insert total row for Singapore
INSERT INTO tma_data2 (office, department, headcount, ...)
SELECT
  office,
  'Total' AS department,
  SUM(headcount) AS total_headcount,
  NULL AS offers_recruitment_firm1, -- original columns set to NULL
  SUM(offers_recruitment_firm1_total) AS total_offers_firm1,
  SUM(offers_recruitment_firm1_senior) AS senior_offers_firm1,
  -- ... aggregated for all columns
FROM tma_data2
WHERE office = 'Singapore';

Step 02 — Create fig1 Table

The CREATE TABLE command is used with CONCAT to join the individual total, senior, and inclusive values back together with the | character. IFNULL ensures that NULL values are replaced with 0.

MySQL 
CREATE TABLE fig1 AS
SELECT
  office, department, headcount,
  CONCAT(IFNULL(offers_recruitment_firm1_total, 0), '|',
         IFNULL(offers_recruitment_firm1_senior, 0), '|',
         IFNULL(offers_recruitment_firm1_inclusive, 0))
         AS recruitment_firm_1,
  -- ... repeated for all firms and acceptances
FROM tma_data2
ORDER BY FIELD(office, 'Singapore', 'Hong Kong', 'Tokyo'),
         FIELD(department, 'IT Systems', 'Corporate Services',
               'Customer Service', 'Operations',
               'Customer Support', 'Total');

Question 1(d)

Creating the easy_data Table

Task Create a new MySQL table named easy_data based on the updated TMA_data table from Q1(b). This new table should contain all the information available in the updated table, excluding the totals column for a table that is easy for further analysis and visualisation.
MySQL 
-- Create easy_data excluding 'Total' rows
CREATE TABLE easy_data AS
SELECT * FROM (
    SELECT
      office, department, headcount,
      offers_recruitment_firm1_total,
      offers_recruitment_firm1_senior,
      offers_recruitment_firm1_inclusive,
      -- ... all individual columns
      acceptance_total_senior,
      acceptance_total_inclusive
    FROM tma_data2
    WHERE department != 'Total'
) AS filtered_data;

Image placeholder — Figure 20
Figure 20: Code to create easy_table that is easy for further analysis and visualisation

The easy_data table is structured this way for three key reasons:

Rationale

1. Separated columns enable analysis: Splitting the xx|yy|zz format into individual columns allows for comparing offers made across the 3 firms, comparing acceptance rates, and performing aggregate calculations.

2. Removed total aggregation columns: The totals for total offers made or accepted across the 3 firms are excluded to remove unnecessary columns, allowing for faster queries to the database.

3. Integer data types: Column 4 onwards are changed to integers since the values are all whole numbers after separation. This allows for proper numerical analysis of continuous data.

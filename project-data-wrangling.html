Design Decision

Only headcount was changed to integer since the column is entirely whole numbers. With only 12 rows, the dataset is small enough that keeping other columns as text has negligible storage impact. The xx|yy|zz format in columns 4–11 requires text to preserve the pipe-delimited structure until the values are properly split in Question 1(b).

Step 01 — Create New Columns

Entries with the pattern xx|yy|zz are split into individual columns. xx refers to total number of offers made or accepted, yy to senior positions, and zz to inclusive positions.

For each recruitment firm, new columns are created following a clear naming convention: offers_recruitment_firm1_total, offers_recruitment_firm1_senior, and offers_recruitment_firm1_inclusive.

The easy_data table is structured this way for three key reasons:

Rationale

1. Separated columns enable analysis: Splitting the xx|yy|zz format into individual columns allows for comparing offers made across the 3 firms, comparing acceptance rates, and performing aggregate calculations.

2. Removed total aggregation columns: The totals for total offers made or accepted across the 3 firms are excluded to remove unnecessary columns, allowing for faster queries to the database.

3. Integer data types: Column 4 onwards are changed to integers since the values are all whole numbers after separation. This allows for proper numerical analysis of continuous data.
